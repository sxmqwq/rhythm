# rhythm · 网易云歌词接龙

入口：https://sxmqwq.github.io/rhythm/

独立项目仓库：https://github.com/sxmqwq/rhythm

搜索歌名、歌手，或粘贴网易云歌曲／公开歌单的完整链接。读取原文歌词，自动保存在当前浏览器；无需登录，不播放音频。

## 玩法

答题方式与接龙方式可自由组合，共四种组合，分别保存连击纪录。

| 选项 | 规则 |
| --- | --- |
| 标准模式 | 完整输入紧接着的下一句歌词 |
| 简易模式 | 每个汉字输入一个拼音首字母，例如“我爱你”填 `wan`；英文、数字和其他文字保留原文 |
| 连续接龙 | 网页只给首句，玩家逐句接到结束 |
| 提示模式 | 网页提示第 1 句，玩家接第 2 句；网页提示第 3 句，玩家接第 4 句，依此类推 |

- 两种答题方式都比较整句，忽略 Unicode 标点、空白、全半角和英文大小写。少字、多字、错字、跳句不通过。
- 首字母使用随项目提供的 pinyin-pro 3.29.5 按词语转换，`zh/ch/sh` 都只取第一个字母。非中文歌词保留原文。
- 提示句不计接对或跳过；歌曲最后只剩一条提示句时，展示该句后结算。
- 答错留在当前句，允许重试，连击清零；查看答案后只能跳过这一题，不计接对。
- 支持从头或随机位置开始。刷新后恢复当前歌曲的模式、位置与纪录。
- 切换模式从头开始；不同模式的纪录分别保存。

## 歌词清理与旧数据迁移

LRC 保留重复副歌和原有顺序，展开多个时间戳，移除增强时间标签、作词作曲等制作署名、独立歌手名称、明确的“歌名 - 歌手”标题行。结合网易云歌曲资料和 LRC 的 `ar` 标签识别歌手。对唱中的已知歌手名、男／女／合标签只删前缀，保留演唱正文。

避免依据字数、位置或“看起来像名字”删除不确定的行；仍可能需要针对特殊歌曲继续补充规则。普通歌词中提到歌手、歌名或作词等词语会保留。

继续使用旧的 `rhythm:netease:v1` 浏览器存储键以及同一网址。自动迁移旧曲库，清理缓存歌词；只有歌词发生变化的歌曲才重置进度及纪录，并提示用户。其他歌曲可以继续原进度。

## 开发与部署

Node.js 24，无需安装构建依赖：

```sh
npm test
npm run build
```

根目录是源码，`dist/` 是可部署的静态产物，构建为本地模块和样式添加内容版本，避免旧缓存混用。`vendor/` 包含拼音库及其 MIT 授权；运行时不请求拼音服务。

仓库的 GitHub Pages Source 设置为 **GitHub Actions**。推送 `main` 后，`.github/workflows/pages.yml` 自动测试、构建并部署 `dist/` 到 `/rhythm/`。本项目独立于博客及 Gmeek 的生成和发布流程，不向 `sxmqwq.github.io` 仓库同步代码。

## 网易云读取服务

GitHub Pages 不运行服务器，网易云原接口不提供浏览器跨域响应，当前通过公开只读适配服务读取数据：

- injahow Meting：歌曲、歌单资料及原文 LRC。
- GD音乐台：网易云搜索及备用原文 LRC。

配置位于 `config.mjs`。请求有超时和备用来源，不携带登录 Cookie，不请求付费音频或音频下载。外部服务不可用时，新歌的导入会受影响，已保存歌曲仍可使用。歌词、标题和歌手信息均通过文本节点显示。
